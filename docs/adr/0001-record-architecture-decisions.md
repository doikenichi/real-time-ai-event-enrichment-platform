# ADR-0001: Record architecture decisions

- **Status:** accepted
- **Date:** 2026-11-26

## Context
This platform is built in small daily steps. Decisions made weeks apart need to stay visible and explainable, both to future me and in client-style conversations.

## Decision
Record significant decisions as lightweight ADRs in `docs/adr/`, numbered sequentially, using `0000-template.md`.

## Consequences
Every non-trivial choice (a tool, a pattern, a free-tier trade-off) gets a short written rationale. Writing ADRs is practice for the "architect solutions and explain trade-offs" part of consulting work.
